# Франшиза — готовые идеи для MAX

Статический адаптивный сайт-каталог готовых ботов и цифровых решений для бизнеса в MAX. Подходит для публикации через GitHub Pages.

## Публикация на GitHub Pages

1. Откройте **Settings → Pages** в репозитории.
2. В разделе **Build and deployment** выберите **Deploy from a branch**.
3. Выберите ветку `main` и папку `/(root)`, затем нажмите **Save**.
4. Дождитесь завершения публикации в разделе **Actions**.

Сайт использует обычные HTML, CSS и JavaScript — сборка, npm и сервер не требуются.

## Что есть на сайте

- Название проекта: «Франшиза — готовые идеи для MAX». MAX используется как название платформы, а не как часть бренда «MAX Бизнес».

- Адаптивная главная страница в светлом сине-белом стиле.
- Каталог из девяти демонстрационных бизнес-направлений.
- Работающие фильтры по категориям.
- Блоки преимуществ и процесса заказа.
- Кнопки обращения к продавцу в MAX; карточки решений открывают бота с deep-link payload выбранного решения.
- SEO-описание, доступные подписи и поддержка prefers-reduced-motion.

## Перед запуском продаж

- Ссылка продавца настроена на `https://max.ru/se14711525_bot`; карточки передают название решения через параметр `start` deep link. Чтобы бот автоматически отвечал на этот payload, отдельно настройте серверный webhook и обработчик MAX Bot API.
- Подтвердите цены, состав услуг и реальные возможности каждого решения. Цены на сайте обозначены как ориентировочные.
- Замените демонстрационные цифры в визуальном макете на реальные данные либо оставьте пояснение, что они условные.
- Убедитесь, что каждый заявленный бот действительно доступен для разработки и запуска. Сайт является витриной; сам по себе он не создаёт, не хостит и не продаёт автоматически работающих ботов.
- Для онлайн-оплаты, личного кабинета или автоматической выдачи потребуются отдельные интеграции; текущая версия направляет покупателя к продавцу.

## Серверная часть MAX на Vercel

В репозитории добавлены Vercel Functions:

- `/api/webhook` — принимает события `bot_started`, `message_created` и `message_callback`, поддерживает callback-нажатия через `POST /answers` и отправляет новые навигационные кнопки как `message`-кнопки для надёжной обработки через `message_created`, отвечает покупателю и сохраняет заявки в Redis, если Redis REST-переменные настроены.
- `/api/setup-webhook` — защищённо регистрирует HTTPS webhook в MAX.

### Переменные окружения Vercel

Добавьте для Production:

- `MAX_BOT_TOKEN` — токен бота MAX (секрет).
- `MAX_WEBHOOK_SECRET` — случайный секрет длиной 5–256 символов, только латинские буквы, цифры, дефис или подчёркивание. Этот же секрет защищает endpoint настройки.
- `WEBHOOK_BASE_URL` — стабильный домен Vercel без протокола, например `franshiza.vercel.app` (укажите фактический Production-домен своего проекта).
- Redis REST URL и token: `KV_REST_API_URL` + `KV_REST_API_TOKEN` либо `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`.
- Необязательно: `MAX_ADMIN_CHAT_ID` — ID чата, куда отправлять уведомления о новых сообщениях покупателей. Не задавайте его, пока не знаете правильный ID.

После добавления/изменения переменных выполните Redeploy. Затем зарегистрируйте webhook одним POST-запросом к Production-домену, передав `MAX_WEBHOOK_SECRET` в заголовке Authorization:

```bash
curl -X POST "https://ВАШ-ДОМЕН/api/setup-webhook" \
  -H "Authorization: Bearer ВАШ_MAX_WEBHOOK_SECRET"
```

При успехе endpoint вернёт `{"ok":true,...}`. Не публикуйте токен или секрет в GitHub, сообщениях или скриншотах.

Важно: GitHub Pages остаётся только статической витриной. API-функции работают на домене Vercel. В MAX должны быть включены доступ и модерация бота, а домен webhook должен поддерживать HTTPS с доверенным сертификатом. Документация MAX: [Webhook](https://dev.max.ru/docs-api/methods/POST/subscriptions), [отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages), [события и диплинки](https://dev.max.ru/docs/chatbots/bots-coding/prepare).

## Продажи и пользовательские сценарии

Серверные модули продаж:
- `lib/sales.js` — каталог продуктов, постоянное хранение сессий и заявок в Redis REST, очередь напоминаний и события воронки.
- `lib/sales-flow.js` — диалог подбора, каталог, карточки решений, демонстрации сценариев, сравнение, возражения, сохранённые решения, настройки согласия и заявки.
- `api/admin.js` — защищённая минимальная панель заявок и фактических событий. Откройте `/api/admin` и введите `ADMIN_API_TOKEN`.
- `api/reminders.js` — защищённый worker очереди напоминаний. Запросите endpoint с заголовком `Authorization: Bearer CRON_SECRET`; ответ содержит счётчики отправленных, пропущенных и повторно запланированных сообщений.

Дополнительные переменные окружения Vercel:
- `ADMIN_API_TOKEN` — длинный случайный секрет для панели администратора.
- `CRON_SECRET` — отдельный длинный случайный секрет для запуска worker напоминаний.
- `REMINDER_DEFAULT_UTC_OFFSET_MINUTES` — резервное смещение часового пояса в минутах для тихих часов 09:00–20:00; по умолчанию `0` (UTC). Если смещение конкретного пользователя известно, его можно хранить в сессии как `timezone_offset_minutes`.
- Уже используемые `MAX_BOT_TOKEN`, `MAX_WEBHOOK_SECRET`, `MAX_ADMIN_CHAT_ID` и Redis REST URL/token остаются необходимыми для соответствующих функций.

### Планировщик напоминаний

Очередь хранится в Redis, а `/api/reminders` проверяет срок, актуальность пользовательской сессии, согласие и статус покупки перед отправкой. Сам endpoint не запускает себя по таймеру: подключите внешний cron/scheduler, который вызывает `POST https://ВАШ-ПРОДАКШН-ДОМЕН/api/reminders` каждые 5–10 минут с `Authorization: Bearer CRON_SECRET`. Не публикуйте секрет. Если внешний scheduler не настроен, напоминания будут оставаться в очереди и не отправятся автоматически.

### Статус оплаты

В текущей реализации нет платёжного провайдера, проверки подписанных webhook оплаты и автоматической выдачи купленного продукта. Кнопка оформления создаёт заявку, а не оплаченный заказ. Не отмечайте заявку как оплаченную вручную без подтверждённого платежа. Для полноценной покупки нужно отдельно выбрать и подключить провайдера, настроить подпись webhook, идемпотентность платежей и выдачу продукта.

### Проверки

Каталог можно проверить встроенным тестом Node.js:
```bash
node --test tests/sales.test.js
```

Перед production проверьте переменные окружения и реальный диалог в MAX. READY у Vercel подтверждает развёртывание кода, но не подтверждает наличие Redis, разрешений MAX, секретов администратора или внешнего планировщика.
