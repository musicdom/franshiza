# UX/UI audit — Норка

Дата: 2026-11-13  
Ветка: `ux/norka-mobile-redesign`

## Объём фактической проверки

Проверены текущие `README.md`, `index.html`, `api/norka.js`, `api/norka-payment.js`, `api/yoomoney/notify.js`, `api/webhook.js`, `vercel.json` и `package.json`. Основной интерфейс находится в одном большом HTML-файле: около 2 117 строк и 321 КБ, со встроенными CSS и JavaScript.

## Фактическая архитектура, которую нельзя ломать

- MAX WebView загружает `index.html`; используется MAX Web App SDK.
- Основной пользовательский API вызывается напрямую по адресу Yandex Cloud Functions (`YANDEX_FUNCTION`) с `X-Norka-InitData`.
- Отдельный поток создания платежа вызывается через `https://franshiza.vercel.app/api/norka-payment`.
- В репозитории присутствуют Vercel API-функции и Redis REST-интеграция; YooMoney callback обрабатывается `api/yoomoney/notify.js`.
- Webhook MAX в репозитории представлен `api/webhook.js`; в интерфейсе есть административное действие повторной настройки webhook на Yandex Cloud.
- `vercel.json` содержит cron для `/api/cron/norka`.

**Архитектурный риск:** README утверждает, что API и Redis работают в Vercel, но фронтенд использует Yandex Cloud для основного API и Vercel только для создания платежа. README и реальная схема маршрутов расходятся. Перед любыми инфраструктурными изменениями необходимо сверить production-конфигурацию и фактическое назначение каждого endpoint. В рамках UX-работы endpoint-ы, авторизация, Redis, webhook и платёжные обработчики не меняются.

## Текущая карта экранов

Пять основных вкладок уже существуют:
1. Главная — `#home`
2. Призы — `#giveaways`
3. Ягоды — `#earn`
4. Кошелёк — `#wallet`
5. Профиль — `#profile`

Внутренние экраны:
- `#exchange` — колесо удачи и обмен ягод на монеты; открывается из раздела ягод.
- `#collection` — достижения; открывается из профиля.

Внутри раздела ягод есть панели: обзор, задания, реферальная программа, рейтинг. В призах есть переключатель обычных и номерных розыгрышей, а также отдельный модальный сценарий выбора номеров. В профиле есть история подарков и административная модальная панель.

## Основные UX-проблемы

### 1. Главная перегружена повторяющимися маршрутами
На главной одновременно показаны путь «Собирай → Меняй → Участвуй», две карточки баланса, ежедневная награда, серия/прогресс, три быстрых перехода и список розыгрышей. Одни и те же действия повторяются в нескольких блоках, поэтому экран не выделяет один следующий шаг.

### 2. Название третьей вкладки не описывает пользовательскую задачу
«Ягоды» обозначает валюту, а не действие. Пользователь ищет способ получить награду; название «Заработать» точнее описывает назначение раздела.

### 3. Обмен спрятан за дополнительным экраном
Обмен и колесо находятся внутри отдельного экрана `exchange`, который открывается из раздела ягод. Самостоятельный пользователь может не понять, что обмен — отдельная функция.

### 4. В разделе ягод смешаны задачи разного приоритета
Задания, приглашение друзей, рейтинг и обмен представлены рядом как равнозначные плитки. Рейтинг не является основным способом получения ягод и визуально конкурирует с заданиями.

### 5. Призы требуют предварительного понимания форматов
Перед списком розыгрышей пользователь видел объяснение и переключатель «Обычный / Номерной». Это добавляло обязательный выбор до знакомства с конкретными призами. Формат логичнее объяснять внутри карточки розыгрыша, не меняя серверные правила.

**Дополнительно обнаружена функциональная ошибка:** серверная функция `giveaways()` возвращает записи розыгрышей со всеми статусами, а клиент до изменений делил их только по типу (`numbers` / обычный), не по статусу. Поэтому завершённые/отменённые записи могли попадать в активный каталог, а кнопка участия оставалась доступной. В UX-ветке добавлена фильтрация по статусам, закрытые розыгрыши больше не получают активную кнопку; на главной показываются только активные.

### 6. Кошелёк объединяет несколько разных намерений
Покупка монет, просмотр балансов и история операций находятся на одном длинном экране. При этом баланс ягод уже показан на главной и в профиле. Нужно визуально разделить покупку, текущий баланс и историю, не удаляя ни одну функцию.

### 7. Профиль повторяет данные других разделов
Профиль снова показывает оба баланса и переход к кошельку, достижениям и истории. Дублирование полезно только как краткое резюме; текущая композиция дополнительно содержит коллекцию подарков и административный вход.

### 8. Обучение новичка отсутствует
В HTML нет onboarding/tutorial/first-visit сценария. Новому пользователю не объясняются четыре базовых шага и назначение двух валют.

### 9. Технические сообщения попадают в пользовательский интерфейс
Bootstrap-ошибка выводит технический код и текст исключения. Для пользователя нужно показывать короткое объяснение и безопасное действие повтора, а техническую диагностику оставлять в консоли/логах.

### 10. Стили и логика трудно сопровождать
CSS и JavaScript встроены в один HTML-файл. Есть повторные объявления ряда селекторов и media queries. Это повышает риск регрессии при точечных правках. Механическое удаление повторов опасно: поздние правила могут намеренно переопределять ранние.

## Целевая информационная архитектура

- **Главная:** приветствие, два баланса, одна ежедневная награда, четыре быстрых действия, компактный блок активных призов.
- **Призы:** единый каталог активных розыгрышей; формат указан в карточке; вкладки/фильтры «Активные», «Завершённые», «Мои участия» — только если данные уже доступны через существующий API.
- **Заработать:** ежедневная награда, каталог заданий и приглашение друга; рейтинг — вторичный пункт.
- **Кошелёк:** баланс монет, отдельная покупка, история операций; обмен остаётся в понятном контексте раздела заработка и не смешивается с оплатой.
- **Профиль:** личные данные, уровень/XP, достижения, приглашённые друзья, подарки и поддержка; административные функции остаются скрытыми от обычных пользователей.

## Уже реализовано в UX-ветке

- Главная освобождена от повторяющейся схемы «собирай → меняй → участвуй» и отдельного блока серии; добавлены четыре конкретных быстрых действия.
- Основная вкладка «Ягоды» переименована в «Заработать» без изменения её внутреннего ID и API-сценариев.
- Добавлено короткое onboarding из четырёх шагов, показываемое после успешной загрузки данных и сохраняющее прохождение в локальном хранилище устройства.
- В каталоге призов убран обязательный переключатель типа: оба формата показываются вместе, формат указан в карточке.
- Добавлены фильтры «Активные», «Завершённые» и «Мои участия» на основе уже возвращаемых полей статуса/участия.
- В клиенте закрытые розыгрыши нельзя отправить на покупку; на главной отображаются только активные.
- Сетевые ошибки начальной загрузки переведены на понятные пользовательские сообщения; техническая диагностика остаётся в логах.

## Ограничения реализации

- Не менять контракты API, endpoint-ы, схему Redis, механику наград, обмена, розыгрышей, номерных билетов, рефералов или платежей.
- Не удалять существующие функции и административные возможности.
- Не считать платежи или начисления успешными до серверного подтверждения.
- Любой редизайн сначала выполнять на отдельной ветке и проверять на реальных сценариях MAX WebView.
- В репозитории нет npm test/build scripts в текущем `package.json`; перед выпуском потребуется как минимум статическая проверка JavaScript и сценарные проверки критических действий.
